

见过最离谱的学习路线：学了半年Java，集合框架、多线程、JVM、Spring Boot、微服务、Redis、Kafka，技术栈列表能写满一页纸。结果面试官问：”你做过什么项目？”“呃……跟着视频敲过一个博客。”“线上出了慢查询，你怎么排查？”“不知道。”“Redis缓存击穿怎么处理？”“背过概念，但没实际用过。”这种情况太常见了。技术栈学了一大堆，但不知道怎么用，遇到实际问题直接懵。问题出在哪？大部分学习路线是按”技术栈的完整度”排的，不是按”你能干什么活”排的。你学完了，但不知道这些技术怎么配合，什么场景用什么。学技术的本质不是把所有技术学会，是建立解决问题的能力。正确的学法是：每学完一个阶段，你就能多干一类活。不是为了学而学，是为了能解决真实问题。第一阶段：能跑起来目标很简单：写个程序，能在本地跑，能看到结果。Java基础语法没什么好说的，变量、循环、判断、函数，跟其他语言差不多。重点是面向对象那套东西：类、对象、继承、多态、接口。很多人卡在这，因为光看概念理解不了。别死磕概念，直接写代码。写个学生管理系统，增删改查。写的时候你会发现，哦，类就是把数据和操作放一起，继承就是复用代码，接口就是定义规范。集合框架必须懂。ArrayList、HashMap、HashSet，这几个是最常用的。不用死记API，知道ArrayList是动态数组、HashMap是哈希表、HashSet底层用HashMap就行。用多了自然记住了。异常处理也很重要。try-catch-finally怎么写，什么时候抛异常，什么时候捕获异常。这个学不好，后面写代码到处try-catch，丑得要命。文件IO和网络IO也得会。读写文件、发HTTP请求，这是最基础的交互。判断标准：你能写个程序，从文件读数据，处理完，输出结果。或者写个程序，调个API拿数据，显示出来。这个阶段就算过了。不要在这个阶段纠结JVM原理、多线程原理这些。你现在还用不上，学了也记不住，等后面需要了再回来补。第一阶段项目示例：图书管理系统（控制台版）写个控制台程序，实现这些功能：添加图书（书名、作者、ISBN、库存）删除图书查询图书（按书名或作者）借书和还书把数据保存到文件，下次启动能读出来能练到啥？类怎么设计、ArrayList和HashMap怎么用、文件怎么读写、异常怎么处理。代码量五六百行，一周能写完。写完你就知道面向对象是怎么回事了。第二阶段：能上线写个Web应用，能部署到服务器上，让别人通过浏览器访问。数据库是第一关。MySQL必须会，增删改查、索引、事务，这是基本功。索引不是背概念，是理解为什么要加、加在哪。没索引的查询是全表扫描，10万条数据要扫10万次。加了索引，用B+树查，最多扫几十次。差距就这么大。where条件的字段需要索引，但也有坑。比如：-- 有索引也会失效
SELECT * FROM user WHERE age + 1 = 18;  -- 在索引字段上计算
SELECT * FROM user WHERE name LIKE '%张';  -- 前缀模糊查询复合索引要注意顺序。(name, age)的索引，WHERE name = '张三' AND age = 18能用上，但WHERE age = 18用不上。事务记住一点：多个操作要么全成功要么全失败。转账是经典例子，扣钱和加钱必须一起成功。实际遇到过的坑：删文章的时候没加事务，文章删了但评论还在，最后用户看到一堆孤儿评论。加上@Transactional，删文章的同时删评论，要么都成功要么都回滚。SQL写得烂会拖垮系统。遇到慢查询，先用explain看执行计划：EXPLAIN SELECT * FROM article WHERE author_id = 123;看type字段，ALL是全表扫描，ref或index是走索引。看rows字段，扫描行数越少越好。遇到慢的，就给where条件的字段加索引。还是慢？看是不是查的字段太多，用覆盖索引。还不行？分页查询，别一次查几万条。然后是Web框架。现在直接学Spring Boot，别学Servlet、JSP那套老古董了。Spring Boot的核心就两个东西：IoC和AOP。IoC就是不用new对象，Spring帮你管。为啥要这么干？举个例子。你写了个UserService，里面要用UserDao。传统写法是UserDao dao = new UserDaoImpl()，写死了。要换实现得改代码。用IoC之后，你写@Autowired UserDao dao，Spring自动注入。要换实现？改配置就行，代码一行不用动。测试的时候可以注入个假的Dao，不用真连数据库。这就是依赖倒置，高层模块不依赖低层模块，都依赖抽象。AOP就是统一处理横切关注点。什么叫横切？就是多个地方都要用的东西：日志、权限、事务。不用AOP的话，每个方法都得写：public void saveUser(User user) {
    logger.info("开始保存用户");
    try {
        transaction.begin();
        userDao.save(user);
        transaction.commit();
        logger.info("保存成功");
    } catch (Exception e) {
        transaction.rollback();
        logger.error("保存失败", e);
    }
}用AOP之后，加个@Transactional，这些代码Spring帮你搞定。代码干净多了。MyBatis或者JPA学一个，用来操作数据库。MyBatis灵活，JPA省事，选哪个都行。我个人推荐MyBatis，灵活度高，遇到复杂SQL不会抓瞎。写个CRUD的Web应用，用户注册登录，发帖回帖，这种最简单的论坛或者博客系统。写完能跑起来，能部署到服务器上，就算过了。判断标准：你能独立写一个增删改查的Web应用，前端调你的接口能拿到数据，能写到数据库。你知道怎么打包、怎么部署、怎么看日志。不要在这个阶段去学Redis、消息队列、微服务。你现在的系统用不上这些，学了也是浪费时间。第二阶段项目示例：个人博客系统写个简单的博客，功能包括：用户注册登录（加密存密码，Session管理）发布文章（标题、内容、分类、标签）评论（一对多关系：一篇文章多条评论）文章列表（分页查询）搜索文章（模糊查询）技术栈：Spring Boot + MyBatis + MySQL前端用模板引擎（Thymeleaf）或者直接Vue/React调API能练到啥？RESTful API怎么设计、数据库表怎么建、多表怎么查、事务怎么管、分页怎么做、索引加哪里、怎么打包部署。代码量两三千行，两到三周。写完就能找初级岗位的实习了。部署流程：# 打包

logging.file.name=app.log出错了，看堆栈信息，定位到具体哪一行。慢查询看MySQL的慢查询日志，找到慢的SQL优化。第三阶段：能扛住系统能承受高并发，出了问题知道怎么查、怎么修。缓存是第一个要学的。Redis必须会，不只是会用，还得理解为什么要用缓存、缓存放哪些数据、缓存怎么更新、缓存穿透击穿雪崩怎么处理。别一上来就背八股文，先理解本质：缓存就是用内存换时间。数据库慢，读缓存快，所以把热数据放缓存里。缓存穿透击穿雪崩这些，不是背概念，是理解场景。穿透：有人故意查不存在的数据，比如id=-1的用户。缓存没有，查数据库也没有，每次都打到数据库。解决办法：缓存空值，或者用布隆过滤器。布隆过滤器能判断”这个数据肯定不存在”，挡在缓存前面。击穿：热点数据过期了，瞬间大量请求打到数据库。比如秒杀商品的缓存过期了，几万个请求同时查数据库。解决办法：加互斥锁，只让一个请求查数据库，其他请求等着。或者热点数据永不过期。代码长这样：public Product getProduct(Long id) {
    String key = "product:" + id;
    Product product = redis.get(key);
    if (product != null) return product;

    // 加锁，只让一个请求查数据库
    String lockKey = "lock:" + id;
    if (redis.setnx(lockKey, "1", 10)) {
        try {
            product = database.get(id);
            redis.set(key, product, 3600);
            return product;
        } finally {
            redis.del(lockKey);
        }
    } else {
        // 其他请求等100ms再查缓存
        Thread.sleep(100);
        return getProduct(id);
    }
}雪崩：大批缓存同时过期，数据库扛不住。比如凌晨统一失效，早上流量来了直接打挂。解决办法：过期时间加随机值，别让缓存集体失效。3600 + random(0, 300)，错开过期时间。消息队列也要学。RabbitMQ或者Kafka选一个。消息队列的核心是解耦和削峰。两个系统不直接调用，通过消息队列传消息，这样一个挂了不影响另一个。秒杀场景请求量太大，先扔消息队列慢慢处理，不会把系统打挂。分布式事务是个大坑。大部分场景不需要强一致，最终一致就够了。实在需要强一致，用Seata或者直接上TCC。微服务不是必须学的。小团队、小项目根本用不上，别被忽悠了。微服务的代价是啥？单体应用一个服务挂了，重启就行。微服务十几个服务，一个挂了，调用链全断。你得有服务发现、负载均衡、熔断降级这一套。单体应用调用是本地方法调用，几纳秒。微服务是网络调用，几毫秒起步。调用链长了，延迟叠加，用户等半天。单体应用出问题看日志就行。微服务链路追踪、分布式日志、监控告警，一套下来运维成本翻好几倍。分布式事务更是大坑。单体应用一个数据库事务搞定，微服务跨多个服务，要么用最终一致性（写一堆补偿逻辑），要么上TCC（复杂度爆炸）。什么时候用微服务？团队超过50人、系统超过10万行代码、不同模块更新频率差异大，这时候微服务的好处才能抵消代价。小团队就老实用单体应用，别给自己找麻烦。如果确实要学微服务，Spring Cloud Alibaba是主流选择：注册中心用Nacos，网关用Spring Cloud Gateway，熔断用Sentinel，配置中心用Nacos Config。Docker必须会。不用深究原理，知道怎么写Dockerfile，怎么打镜像，怎么跑容器就行。判断标准：你能设计一个能扛住几千QPS的系统，知道哪些地方会成为瓶颈，知道怎么优化。你知道怎么用缓存、怎么用消息队列、怎么做限流熔断。系统出问题了，你能通过日志和监控快速定位原因。第三阶段项目示例：电商秒杀系统在博客系统的基础上，加个秒杀功能：商品列表和详情秒杀倒计时下单（库存扣减、订单创建）防止超卖防止刷单重点优化这些：用Redis缓存热点商品信息（减少数据库查询）用Redis预扣库存（避免数据库锁竞争）用消息队列异步处理订单（削峰）接口限流（防止单用户刷接口）分布式锁（防止超卖）能练到啥？Redis怎么用、缓存怎么更新、消息队列怎么接、分布式锁怎么加、限流怎么做、压测怎么跑、监控怎么搭。代码量五千行起步，一个月左右。写完你就知道高并发系统咋回事了。这三个项目难度递增，每个都能实际跑起来看效果。不是为了项目而项目，是为了把技术点串起来，理解它们在真实场景下怎么配合。常见的坑说几个大部分人会踩的坑。学太多用不上的技术。很多人照着路线图学，学了一堆框架，工作了发现公司就用Spring Boot + MyBatis + Redis，其他都用不上。别追求学全，追求学精。把常用的技术吃透，比浅尝辄止地学一堆强得多。基础不扎实就跳框架。集合框架、多线程、JVM都没搞懂，就开始学Spring
